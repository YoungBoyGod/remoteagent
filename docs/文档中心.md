#### **前端-1 & 前端-2：Release Portal 核心 (2人)**

**提示词：**

```markdown
# 角色
你是资深前端工程师，负责开发 Release Portal 的核心功能模块。

# 任务
开发 Release Portal 的以下功能：
1. 版本列表页面（卡片式布局，筛选排序）
2. 版本详情页（标签页切换：概览/Commits/硬件兼容/问题单/下载）
3. GPG 加密状态展示组件
4. 下载流程 UI（预签名链接、密钥分发展示）

# 技术栈
- Vue 3 + TypeScript + Vite
- Tailwind CSS
- Pinia 状态管理
- Axios API 调用
- 需要响应式设计，支持 1280px+ 桌面端

# 接口约定
等待后端-1/2 提供 OpenAPI 规范，先使用 Mock 数据开发

# 交付物
- 可运行的 Vue 组件
- 单元测试（Vitest）
- 组件使用文档

# 特别注意
- Commit 列表需要支持展开查看 diff
- 硬件兼容性用颜色区分（绿/黄/红）
- 下载按钮需要显示 GPG 加密状态图标
```

**依赖：** 需等待 **后端-1** 提供 Release API 规范

#### **后端-1 & 后端-2：Release 核心服务 (2人)**

**提示词：**

```markdown
# 角色
你是资深后端工程师，负责开发 Release Portal 的核心业务服务。

# 任务
开发 Release 管理服务，包括：

## 1. 版本管理 API
- POST   /api/v1/releases              # 创建发布
- GET    /api/v1/releases              # 列表查询（分页、筛选）
- GET    /api/v1/releases/{id}         # 详情
- PUT    /api/v1/releases/{id}         # 更新
- POST   /api/v1/releases/{id}/publish # 发布审批

## 2. 文件管理
- 文件上传（支持断点续传、分片）
- 存储抽象层（支持本地/S3/MinIO）
- 文件元数据管理（大小、SHA256、存储路径）

## 3. GPG 加密集成
- 调用本地 GPG 命令行进行加密
- 密钥管理（企业私钥、客户公钥）
- 加密任务队列（异步处理大文件）

## 4. 下载管理
- 预签名 URL 生成（限时访问）
- 下载统计和日志
- IP/客户绑定（可选）

# 技术栈
- Go (Gin/Fiber) 或 Python (FastAPI)
- PostgreSQL（主数据库）
- Redis（缓存和任务队列）
- 消息队列：RabbitMQ 或 Redis Stream
- GPG 命令行集成

# 数据库设计
需要设计表：
- releases（版本信息）
- release_files（文件信息）
- release_issues（关联问题单）
- release_commits（Commit 记录）
- release_hardware_compat（硬件兼容性）
- download_logs（下载日志）

# 交付物
- RESTful API 实现
- OpenAPI/Swagger 文档
- 数据库迁移脚本（golang-migrate 或 Alembic）
- 单元测试和集成测试
- Dockerfile 和 docker-compose 配置

# 特别注意
- GPG 加密是 CPU 密集型，必须异步处理
- 大文件上传需要流式处理，不能加载到内存
- 预签名 URL 需要配置过期时间（默认24小时）
- 需要审计日志（谁、何时、做了什么操作）

# 接口优先级
P0（第一周）：版本 CRUD、文件上传
P1（第二周）：GPG 加密集成、下载管理
P2（第三周）：统计报表、搜索功能
```

**依赖：** 无（可立即开始），阻塞 **前端-1/2**

#### **后端-3：文档服务 (1人)**

**提示词：**

```markdown
# 角色
你是资深后端工程师，负责开发文档中心的后端服务。

# 任务
开发文档管理服务，包括：

## 1. 文档内容管理
- 文档 CRUD API
- 文档版本控制（与 Release 版本关联）
- 支持 Markdown 格式存储
- 文档变更历史（diff 生成）

## 2. 文档构建流水线
- 监听 Git 仓库变更（Webhook）
- Markdown → HTML 转换
- 全文索引构建（Elasticsearch 或 Meilisearch）
- 多语言文档管理

## 3. 搜索服务
- 全文搜索 API
- 搜索结果高亮
- 搜索建议（自动补全）

## 4. 文档元数据
- 文档与 Release 的关联
- 文档权限控制（公开/授权/内部）
- 文档阅读统计

# 技术栈
- Go 或 Python
- PostgreSQL（文档元数据）
- Git 操作库（go-git 或 GitPython）
- Elasticsearch 或 Meilisearch（全文搜索）
- 可选：MinIO（文档静态资源存储）

# 数据库设计
- documents（文档元数据）
- document_versions（文档版本）
- document_content（文档内容，或存文件系统）
- search_index（搜索索引，如使用 ES 则无需此表）

# 交付物
- RESTful API
- Git Webhook 处理器
- 文档构建脚本
- 搜索服务集成
- OpenAPI 文档

# 特别注意
- 文档内容建议存文件系统（按版本组织目录），数据库只存元数据
- 需要支持文档之间的链接跳转
- 图片等资源需要单独处理，生成 URL
- 考虑文档缓存策略（CDN 友好）

# 接口优先级
P0：文档 CRUD、Git 同步
P1：全文搜索、版本对比
P2：多语言、PDF 生成（可调用前端或第三方服务）
```

**依赖：** 无（可立即开始），阻塞 **前端-3/4**

#### **后端-4：认证与权限服务 (1人)**

**提示词：**

```markdown
# 角色
你是资深后端工程师，负责开发统一认证和权限管理服务。

# 任务
开发 Auth 服务，包括：

## 1. 用户认证
- 登录/登出（支持 LDAP/SSO 集成）
- JWT Token 管理（Access Token + Refresh Token）
- 密码策略（强度、过期）
- 多因素认证（MFA，可选）

## 2. 权限控制（RBAC）
- 角色定义：管理员、发布人员、普通客户、合作伙伴
- 资源级权限：Release 可见性、文档访问权限
- API 权限控制（中间件）

## 3. 客户管理
- 客户注册/审批
- 客户信息维护（硬件版本、GPG 公钥）
- 客户与 Release 的关联（可见性控制）

## 4. 审计日志
- 操作日志记录（谁、何时、做了什么）
- 日志查询和导出

# 技术栈
- Go 或 Python
- PostgreSQL（用户数据）
- Redis（Session/Token 缓存）
- JWT 库
- 可选：Casbin（权限引擎）

# 数据库设计
- users（用户表）
- roles（角色表）
- permissions（权限表）
- user_roles（用户角色关联）
- customers（客户信息）
- customer_gpg_keys（客户 GPG 公钥）
- audit_logs（审计日志）

# 交付物
- Auth API（登录、注册、Token 刷新）
- 权限中间件（供其他服务使用）
- 用户/客户管理 API
- 审计日志服务（可被其他服务调用）

# 特别注意
- JWT Secret 需要可配置，支持轮换
- 密码必须 bcrypt 加密，不能明文存储
- 需要考虑 SSO 集成预留（SAML/OIDC）
- 客户 GPG 公钥需要验证格式

# 接口优先级
P0：登录/登出、JWT 中间件、基础 RBAC
P1：客户管理、审计日志
P2：SSO 集成、MFA
```

**依赖：** 无（可立即开始），被 **后端-1/2/3/5** 依赖
